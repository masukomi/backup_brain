#+TITLE: Backup Brain systemd Services
#+DESCRIPTION: How to configure and install the systemd units in this directory

These files let you run Backup Brain and its dependencies as systemd services
so they start automatically on boot and restart on failure.

* Files

| File                                | Purpose                                                     |
|-------------------------------------+-------------------------------------------------------------|
| =backup_brain.service=              | Main Rails app (Puma)                                       |
| =backup_brain_delayed_job@.service= | Template unit for background job workers (one per instance) |
| =meilisearch.service=               | Meilisearch search engine                                   |
| =meilisearch.toml=                  | Meilisearch configuration (goes to =/etc/meilisearch.toml=) |
| =tailscale_funnel=                  | Script invoked by =tailscale_funnel.service=                |
| =tailscale_funnel.service=          | Optional: exposes Backup Brain via Tailscale Funnel         |

* Required Changes Before Installing

** =backup_brain.service= and =backup_brain_delayed_job@.service=

Both files share the same set of placeholders:

| Placeholder             | Replace with                                                     |
|-------------------------+------------------------------------------------------------------|
| =YOUR_USERNAME=         | The OS user that will run the app (e.g. =alice=)                 |
| =USER_GROUP=            | That user's primary group (e.g. =alice= or =www-data=)           |
| =/path/to/backup_brain= | Absolute path to the repo root (e.g. =/home/alice/backup_brain=) |
| =RAILS_ENV=development= | Change to =production= if running in production mode             |

To adjust the number of background job workers, edit the =Wants= and =After=
lines in =backup_brain.service=. The default is 2 workers:

#+begin_src ini
Wants=backup_brain_delayed_job@1.service backup_brain_delayed_job@2.service
After=backup_brain_delayed_job@1.service backup_brain_delayed_job@2.service
#+end_src

Add or remove entries (=backup_brain_delayed_job@3.service=, etc.) to change the count.

** Running in production mode

Choosing =production= in =setup.sh= (or setting =RAILS_ENV=production= by hand)
makes Rails stricter than development. The repo handles most of it, but one
value must come from you:

- =SECRET_KEY_BASE= must be set in =.env=. Rails refuses to boot without it, and
  the =serve= script exits early with instructions if it's missing. Generate one
  from the repo root with:

  #+begin_src sh
  echo "SECRET_KEY_BASE=$(bin/rails secret)" >> .env
  #+end_src

Production uses its own database, =backup_brain_production= (see
=config/mongoid.yml=). =scripts/export.sh= and =scripts/import.sh= default to
=backup_brain_development=, so when moving data to a production install run:

#+begin_src sh
DATABASE_NAME=backup_brain_production scripts/import.sh
#+end_src

Things that happen automatically in production mode:

- =HOST_NAME= from =.env= is added to Rails' allowed hosts, alongside
  =localhost= and =127.0.0.1=. Visiting the app via any other hostname or IP
  gets a 403. Development ignores this entirely, so a =.env= that worked in
  development may still need =HOST_NAME= changed: set it to exactly the host
  part of the URL remote browsers use (no port), e.g. =192.168.1.20= or
  =bb.example.lan=.
- Rails writes its log to =log/production.log= in the repo, not to the journal.
  =journalctl -u backup_brain= only shows output from =serve= itself (the
  startup checks, migrations, asset precompile and puma's own messages).
- =serve= runs =rails assets:precompile= before starting puma, because
  production doesn't compile CSS and JavaScript on demand.
- puma serves those precompiled files itself (there's no nginx in this setup).
  Set =RAILS_SERVE_STATIC_FILES=false= in =backup_brain.service= if you add a
  reverse proxy that handles =/assets=.

After pulling changes that touch the =.service= files, re-run =setup.sh= (or copy
them to =/etc/systemd/system/= and run =sudo systemctl daemon-reload=). A =git
pull= alone doesn't update the installed units.

** =meilisearch.toml=

| Placeholder             | Replace with                                                              |
|-------------------------+---------------------------------------------------------------------------|
| =YOUR_MASTER_KEY_VALUE= | Your Meilisearch master key. Generate one with: =openssl rand -base64 32= |

This same key must also appear in your =.env= file as =MEILI_MASTER_KEY=.

The other values in the file are sensible defaults. Adjust =http_addr= if
you need Meilisearch to listen on a different address or port.

** =tailscale_funnel.service=

| Placeholder                                | Replace with                                                     |
|--------------------------------------------+------------------------------------------------------------------|
| =/path/to/scripts/daemon/tailscale_funnel= | Absolute path to the =tailscale_funnel= script in this directory |

The =tailscale_funnel= script exposes port 3334. If your app runs on a
different port, edit that script before installing.

This service is optional — only needed if you are using Tailscale Funnel
to expose Backup Brain over the internet.

* Installation

Copy the files you need to =/etc/systemd/system/= and reload systemd.

** Meilisearch (if not already installed as a service)

#+begin_src sh
sudo cp meilisearch.service /etc/systemd/system/
sudo cp meilisearch.toml /etc/meilisearch.toml
sudo systemctl daemon-reload
sudo systemctl enable --now meilisearch
#+end_src

** Backup Brain + delayed job workers

#+begin_src sh
sudo cp backup_brain.service /etc/systemd/system/
sudo cp "backup_brain_delayed_job@.service" /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now backup_brain
#+end_src

Enabling =backup_brain= is sufficient — it will start the =backup_brain_delayed_job@N=
instances automatically via =Wants=. You do not need to enable the
=backup_brain_delayed_job@.service= template or individual instances separately.

** Tailscale Funnel (optional)

#+begin_src sh
sudo cp tailscale_funnel.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now tailscale_funnel
#+end_src

* Troubleshooting

** =backup_brain_delayed_job@N.service= fails with =status=127=

The shell cannot find =bundle=. The login shell loaded by =-lc= may not have
the right =PATH= for the user the service runs as.

Find the full path to =bundle=:

#+begin_src sh
which bundle
# or, if using rbenv:
ls ~/.rbenv/shims/bundle
#+end_src

Then update =ExecStart= in =backup_brain_delayed_job@.service= to use the full path:

#+begin_src ini
# rbenv:
ExecStart=/bin/bash -lc "/home/YOUR_USERNAME/.rbenv/shims/bundle exec rake jobs:work"

# system bundle (adjust path to match `which bundle`):
ExecStart=/bin/bash -lc "/usr/local/bin/bundle exec rake jobs:work"
#+end_src

After editing, reload and restart:

#+begin_src sh
sudo systemctl daemon-reload
sudo systemctl restart "backup_brain_delayed_job@*"
#+end_src

** =backup_brain_delayed_job@N.service= fails with =status=200/CHDIR=

=WorkingDirectory= in =backup_brain_delayed_job@.service= still contains the
=/path/to/backup_brain= placeholder. Update it to the absolute path of the
repo on this machine.

** =backup_brain.service= stops with =Missing `secret_key_base` for 'production' environment=

You're running in production mode without =SECRET_KEY_BASE= in =.env=.
See "Running in production mode" above.

** Works on the server but remote browsers get a 403 in production

Host authorization is rejecting the hostname or IP the remote browser used.
Confirm with:

#+begin_src sh
grep -i "blocked host" log/production.log | tail
#+end_src

Set =HOST_NAME= in =.env= to that exact host and restart =backup_brain=.
(Nothing shows up in =journalctl= for this: see "Running in production mode".)

** CSS and JavaScript fail with assorted 4xx errors in production

Requests for =/assets/...= are reaching the router instead of being served as
files, and the catch-all =ScriptKiddiesController= answers with a random 4xx.
Either =rails assets:precompile= hasn't produced =public/assets= (=serve= runs it
on start in production; check the journal) or static file serving is off
(=RAILS_SERVE_STATIC_FILES=false= somewhere in the environment).

** =meilisearch.service= fails with =status=200/CHDIR=

=/var/lib/meilisearch= doesn't exist. =setup.sh= creates it, but if you
installed by hand run =sudo mkdir -p /var/lib/meilisearch=.

* Managing the Services

#+begin_src sh
# Start / stop / restart the app (also starts/stops delayed_job workers)
sudo systemctl start backup_brain
sudo systemctl stop backup_brain
sudo systemctl restart backup_brain

# Check status
sudo systemctl status backup_brain
sudo systemctl status "backup_brain_delayed_job@*"

# View service output (startup checks, migrations, puma)
journalctl -u backup_brain -f
journalctl -u "backup_brain_delayed_job@1" -f

# View Rails' own log (requests, errors, blocked hosts). RAILS_ENV=development
# writes log/development.log instead.
tail -f /path/to/backup_brain/log/production.log

# Reload systemd after editing a service file
sudo systemctl daemon-reload
#+end_src
